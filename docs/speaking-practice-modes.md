# Speaking practice modes

Standalone Speaking offers Timed practice and Untimed practice. Timed is the default, including saved attempts created before this change. The selected preference belongs to the current browser account, and each new attempt saves its own validated `practiceMode`. History, adjacent-question lookup, copied links and reattempts retain the matching mode. An existing attempt cannot be relabelled through a repeated create request.

Timed practice retains preparation and response countdowns. Audio tasks start preparation after the prompt actually ends. Untimed practice plays the prompt, waits at Ready when you are, and records only after Start recording. There is no preparation or response deadline; the student finishes with Submit response. Replay prompt is available before recording. The existing recording-size safety limit still applies, with incremental capture stopping before the upload limit rather than discarding a large recording.

The thirty original RTS practice situations were marked text-only. Their practice presentations now expose a private prompt-audio endpoint, rendered from the server-owned saved question snapshot. Existing bundled RTS audio remains in use for the six already narrated situations. Narration uses the installed Edge neural voice, caches by text and narration version, shares concurrent work, and rejects failed or empty output. The client downloads private audio with its session header, supports playback retry, aborts on navigation, and never puts a session token in an audio URL. A cold prompt may show Preparing prompt audio before playback; preparation does not start during generation or download.

Mocks retain their original timing, question snapshots and scoring. Exact source compatibility pins permit the reviewed standalone transport change while preserving Full Mock native transcription, saved provider settings and completed grades. The prediction-rollout regression checks the unchanged Full Mock transcription function separately from the intentionally changed standalone transport.

Verification covers real API mode persistence and ownership, immutable mode retries, saved-text narration, cache reuse and failure recovery, untimed manual capture, timed post-audio preparation, mode-specific history and navigation, and desktop/mobile-width Chromium with synthetic microphone and injected prompt audio. These checks do not establish physical-device microphone support or editorial listening quality of generated speech.
