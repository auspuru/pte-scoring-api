# Speaking mock background assessment

`SPEAKING_PROGRESSIVE_SCORING=true` enables progressive assessment. New attempts pin `progressive-v1`, both delivery providers, and the Academy DI backend. Turning the flag off stops new enrollment; workers continue pinned attempts. Writing scoring and the task-weighted Speaking formula are unchanged.

Each successful recording upload enqueues an idempotent answer job. A periodic cursor scan closes the save/enqueue crash gap, submits expired mocks, and resumes pending work without a browser. PostgreSQL claims use leases, fencing tokens and `SKIP LOCKED`. Successful stages are saved in small job records; original audio stays in the existing attempt. Workers fetch one recording at a time. Progress polling excludes all base64 audio. Verified stages are merged into a submitted attempt once, preserving concurrent instructor overrides and recordings.

Content, OpenAI delivery and Azure delivery must be valid for every question before publication. Explicit skips, unvisited questions at expiry and confirmed zero-content gates remain in the denominator as zero. Missing, provisional and stale marks remain pending. API detail, history and recording review withhold the report until both provider totals are complete. Students see a preparing banner and automatic status polling; no scoring Retry button is required. Five to ten minutes is an expectation, not a provider SLA.

DI uses `VISUAL_ACADEMY_SCORING_URL` and a scoped `PTE_DI_SERVICE_KEY`, shared only with Academy. It sends verified image facts, the saved automatic transcript and normalized WAV. It does not forward account sessions or provider keys. The Academy service uses its canonical combined content/coaching reviewer and audio scorer with the approved `intelligibility-delivery-v5` policy. Azure is independently assessed in PTE. Both totals share the same verified Academy content. A prepared receipt is persisted before submission; lost responses recover by the same job ID. Remote hashes and contract versions are checked before accepting marks.

Workers retain successful companion traits and Azure chunk transcripts/results. Known temporary failures and validation failures have a bounded three-attempt budget with backoff. Service transport retries are idempotent. A stale in-flight paid call or explicitly uncertain outcome is held for staff review, because another provider call could incur a duplicate charge. Authentication/configuration failures are also held. These cases never become zero marks and never require a student to resubmit audio.

Admin diagnostics: `GET /api/admin/speaking-mocks/:username/:id/scoring` using the existing admin authentication. Held jobs also emit structured `scoring-job` logs containing IDs and failure codes, never audio or transcripts. A staff repair uses `POST` to the same path plus `/retry`, with `{jobId, stage, operation}`. `operation` is a unique audit ID; repeating it does not rescore. Only held stages can be retried. After inspecting provider usage, an uncertain call additionally requires `acknowledgeUncertain:true`. For an Academy failure the repair is forwarded to its authenticated internal route first. The student page continues polling throughout.

Deploy the backward-compatible Academy service and verify authenticated capabilities before enabling PTE. Existing valid historical reports are retained without bulk paid regrading. Incomplete historical mocks resume when opened; pending mocks also resume in the background scan. Account deletion cascades to PostgreSQL answer jobs.

Validation covers upload-time scoring, complete-only publication, cross-account protection, automatic provider retry, restart recovery, idempotent DI handoff, approved delivery policy, durable PostgreSQL claims and UI transition from waiting to the full report.
