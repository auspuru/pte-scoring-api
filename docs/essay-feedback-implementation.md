# Essay feedback implementation

Policy version: `essay-feedback-2026-10-15.1`. Scoring rubric and maxima remain unchanged. Baseline production commit: `3af884e05c1d2949d532530f0cd3927200c8ec45`.

The complete essay route remains `/api/essay/grade`. Writing Lab and full mocks use the same `createEssayGrader`; plan and generated-draft review is unchanged.

## Implemented behaviour

`public/essay-feedback.js` defines the shared teaching policy, canonical prompt requirements with exact character spans and grouped OR choices, validated issues, final reconciliation, revision comparisons and safe rendering. Each assessment stage uses the same requirements. Existing primary, independent and conditional resolver calls are retained. A feedback disagreement can also require adjudication. The final subjective decision replaces earlier subjective issues, priorities, strengths and verdict. Genuine primary spelling, grammar and vocabulary diagnostics remain available. Minor grammar corrections remain accessible without changing the existing Grammar scoring rule.

Issues identify their code, category, priority, requirement, trait, holistic scoring rationale, current-draft evidence and policy version. Missing coverage references the exact prompt requirement. Other issues require exact current essay evidence. The server materialises numbered-word citations and verifies locations. Evidence existence is a structural safeguard; semantic correctness is a model judgement that must also be evaluated by teaching review.

Results present overall assessment, strengths, up to three main corrections, expandable additional corrections, language corrections and optional polish. Passages are highlighted using verified character offsets and escaped text. Exercises reference issue IDs and the actual issue passage/action. Learning samples are requested separately in the new flow, reusing cached assessment scores; legacy callers retain their existing sample contract.

Revision links are additive fields inside the existing per-user JSON attempt history, including PostgreSQL JSON storage. No database migration is needed. The server loads a parent only from the authenticated account and rejects a changed question. Previous scores are never passed to scoring stages. Resolved claims require current evidence, current requirement coverage and final consistency; uncertain changes are labelled needs clarification. The original text remains immutable. Students can mark a final draft; original, latest and final drafts stay prominent, with intermediate drafts recoverable. History limits retain the original alongside retained revision groups. Existing history limits and explicit deletions still apply.

## Release controls

The feature is disabled by default. `ESSAY_FEEDBACK_V3=true` enables the control, `ESSAY_FEEDBACK_V3_USERS` permits a comma-separated list of verified account usernames, and `ESSAY_FEEDBACK_V3_PERCENT` selects a stable account cohort from 0 to 100. Anonymous requests retain the legacy path. New and legacy assessments have separate versioned caches. Revision context is included in deduplication keys. Attempt IDs are scoped after caching so another account never receives someone else's revision IDs.

Set `ESSAY_FEEDBACK_V3=false` and redeploy to restore the legacy contract for new submissions. Saved new results remain readable through the compatible legacy fields and additive renderer. Reverting the release commit restores the previous renderer while keeping historical JSON data. Disable cohort access before a code rollback. There are no destructive migrations to reverse.

`[essay-assessment-metric]` logs policy version, elapsed time, provider call count, completion/failure and error code, without prompts, essays, identities or credentials. Metrics cover assessment/review/resolver and bounded repair operations; explicit sample requests are separate. Use the same interval and workload to compare p50/p95 latency, failures and provider calls. Do not infer live performance from offline unit timings.

## Verification

The baseline passed 679 tests. The final implementation passes 722 tests plus existing offline calibration controls. New tests cover exact requirements, OR alternatives, final-authority replacement, structured evidence, optional advice, zero-correction answers, revision ownership, failure behaviour, caching, call counts, issue-linked exercises and historical retention. Existing essay, mock, navigation and client recovery tests remain in the release gate.

`tests/essay-feedback-cases.js` provides synthetic teaching cases and weaker variants. `scripts/evaluate-essay-feedback.js` submits them only to an explicitly configured isolated review service, records complete results and timings, and repeats selected cases with semantically identical paragraph spacing to avoid returning only cached results. Contract tests alone do not prove model teaching accuracy.

Local build validators passed through the media and content checks, but this environment could not download the Puppeteer browser because the outbound proxy timed out. The hosted release gate must complete the browser installation and full build before promotion. One pre-existing 25 ms SWT timeout test failed during concurrent browser/dependency downloads; its isolated rerun and the subsequent complete suite passed, without modifying SWT code.

The review service is `pte-essay-feedback-review` in `airy-embrace`, service `5bae0f28-26de-407a-9ae8-29a8538ba362`. It has its own ephemeral filesystem, no volume mount, blank database URLs, no shared environment variables and no mail credentials. It references only the existing Claude credential server-side. It does not reuse production student data. Test registrations and attempts are disposable. App sleeping is enabled.

Production-wide activation requires the plan's human teaching review, satisfactory hosted/model/browser evaluation and a gradual cohort release. Do not report human acceptance, production p50/p95 equivalence or full release as completed without that evidence.

## Live evaluation and review outcome

The isolated hosted gate and GitHub CI initially passed all 707 tests, the 136-test build subset, calibration controls, narration/content validators, Edge TTS and the downloaded Puppeteer executable. Subsequent regression coverage now includes 722 tests.

Live model checks exposed two integration faults that mocked contract tests could not establish: the prose output example still named only legacy fields, and demanding a correction for every below-maximum holistic mark encouraged fabricated repairs. The output example now matches the tool contract. A sufficient essay can retain a good holistic mark without a manufactured correction; every reduced trait still needs its rubric explanation, and every missing/partial canonical requirement needs an issue. A single targeted feedback-format repair may reconstruct malformed feedback from existing judgements and current evidence. It cannot alter scores or coverage. A formatting failure does not restart scoring or publish a result. A coverage/issue contradiction instead bypasses the formatter and uses the existing stage's bounded semantic reassessment (at most two attempts), with explicit instructions to credit sufficient explanations or identify a genuine gap. Persistent conflicts fail closed and suppress immediate duplicate paid retries. Repeated identical formatting failures are suppressed briefly to prevent credit-consuming retries.

An inconsistent minimal-relevance label with a higher Content score remains a rejected candidate. Every other field is validated, an independent assessment and resolver are required, and no candidate score is cached or released unless the final normalizer accepts a consistent decision. Standalone score validators continue rejecting the inconsistency; no relevance score is silently clamped or invented. Overlapping quotations identifying the same independently confirmed issue do not themselves force another resolver call.

Eight synthetic cases passed real model evaluation: reasons OR experience, explicit own experience, supported one-sided agreement, an explanation elsewhere in the essay, jobs and automation, relative comparison, office design versus location, and a contradictory conclusion. The design fixture deliberately includes a valid design effect alongside misplaced location discussion. Real results credit that detail while identifying the category mismatch. Selected strong and comparison cases were run again during contract repair. Full sample responses and concise evidence are available in the review preview; no student records or credentials are included.

The small live sample includes intermediate contract revisions. It observed two calls for a straightforward sufficient answer and up to five for complex disagreement/repair cases; complex cases can take more than two minutes. These timings are recorded in `essay-feedback-live-validation.json` and are not a matched production latency baseline or p50/p95 equivalence claim. New-flow samples are optional, and no unconditional assessment call was added for prose polish. Production p50/p95, failure rate and cohort cost comparison remain release-monitoring tasks.

Release decision: keep production-wide activation disabled pending Puru's teaching review and a satisfactory small production cohort. The review preview is `/essay-feedback-preview.html`. Production data is untouched by synthetic evaluation. The implementation and compatible legacy fields can be deployed with the feature disabled; use the documented kill switch before any code rollback.

A live revision walkthrough identified an overly broad local safeguard: it blocked resolution of an old reasoning issue whenever any development weakness remained on the same requirement. Resolution now follows the specific prior issue; coverage issues still require current coverage, and an unchanged flagged passage remains open. Distinct current issues retain their own evidence. The policy also explicitly credits already supplied conditional mechanisms rather than demanding every concluding qualifier be developed.

The live preview also exposed invented first-person examples in a missing-own-experience suggestion. For that specific canonical missing requirement, the server now supplies a deterministic request for the student's genuine observation rather than a fabricated story. OR alternatives do not trigger this safeguard or make a personal story compulsory.

`scripts/evaluate-essay-revisions.js` exercises a disposable synthetic account on an explicitly named isolated review host: resolved-issue evidence, linked attempts, save/reload, cached retry, duplicate prevention, original preservation, final marking and account isolation. It never reads production student data.

A further live check found that an otherwise valid final score could omit all prior-issue decisions. The contract now requires every prior ID exactly once and repairs omissions with the feedback-only operation. A disagreement about resolution status also requires final adjudication. Revision context excludes prior score rationales and deduction metadata. Conservative evidence checks still prevent unsupported resolved claims.

The live revision walkthrough passed on `bf7861ddc797c9e352b7c4d74fd19a905fd24e62`: both prior reasoning issues were resolved with exact current evidence, the original scores/text were preserved, linked attempts and the final marker survived save/reload, an identical retry reused the assessment and did not duplicate history, and another account could neither load the parent nor read the owner's records. A ninth preview example shows the revised response and its verified resolutions. Two additional strong-answer runs retained full Content and zero mandatory issues. These remain synthetic checks, not human teaching acceptance or a production latency baseline.

## Returning-browser compatibility fix (16 October 2026)

The initial rollout missed an immutable-cache interaction: `essay-scoring.js` changed while its URL still used the pre-rollout version. A returning browser could therefore reject a completed assessment with `sample_status` and repeat the same cached request. The exact pre-rollout validator reproduced this failure. Essay script URLs now include content hashes, with release tests enforcing them. Optional sample status is negotiated separately from the unchanged scoring rubric version; tabs without the capability header receive an existing, supported sample status and an accurate note, while scores and feedback remain unchanged. Zero-Form results retain the existing unavailable-sample contract and require no paid calls. The production feature was temporarily disabled during investigation.

All 727 tests pass, including a returning-browser rendering check, HTTP capability negotiation, score preservation, zero-Form handling and immutable asset version checks. The actual pre-rollout validator and the current validator both accept the adapted live-model fixture with identical scores.
